# 安装与部署执行路线

这些步骤由 AI 执行，不是交给用户照抄的清单。产品卡决定具体路线；本文提供各路线的执行骨架。每次实施都从官方当前文档解析确切命令、平台支持和认证方式。不得猜包名、端口、模型 ID、扩展发行者或配置字段。

## 共通准备

1. 在实际目标执行 `python scripts/inspect_environment.py`，记录结果到私密任务目录。Python 不存在就用本机系统命令取得同等信息，不为了探测安装大型依赖。
2. 确认浏览器/终端/文件操作工具可用；安装远端软件必须在远端执行。不要用当前 AI 云容器的 GPU 结论代替用户电脑。
3. 读官网产品页、下载页、快速入门、系统要求、模型卡。搜索只作定位；执行参数回到原厂文档确认。文档有 `llms.txt` / `llms-full.txt` 时可读取其索引，但不猜其一定存在。
4. 复用现有正确安装和账户；检查版本和配置是否匹配当前产品。只备份计划修改的配置。任务目录记录已完成步骤和 PID/服务名，重试时查询而不重复安装。
5. 执行安装时保留退出码和有限日志，遮蔽凭据。不要关闭杀毒软件、TLS 校验、系统防护或全局代理来“修复”安装。

## WEB：官方网页

1. 在授权的交互浏览器打开产品卡入口，检查地址栏与当前页面。不把搜索广告或名称近似域名当官网。
2. 读取快照/可访问性树，关闭遮挡内容的普通弹层，保留需要用户决定的协议/隐私和授权选项。
3. 登录优先复用已有会话；到本人扫码、验证码、Passkey、实名或付款关卡时才请用户完成该项，然后继续。
4. 选择产品卡所需功能，核对当前套餐与额度；默认现有免费/已订阅能力。输入一个无敏感样例，提交一次，保存任务 ID 或对话 URL。
5. 等任务真实成功；预览结果；需要交付文件则下载到约定输出目录并实际打开。登录页、排队页和错误页均不能记 ready。
6. 保留工作台/项目入口，必要时添加用户授权的书签或官方 PWA。创建 PWA 只算网页入口，不宣称原生客户端。

## APP：官方客户端、IDE、AI 浏览器

1. 从官网的下载按钮进入官方发行/CDN/应用商店。确认系统、架构、版本；移动 App 的发行者必须与品牌一致。
2. Windows 优先用户级官方安装器或已核对 ID 的包管理器。先查看帮助/官方说明才使用静默参数；不要对任意 exe 猜 `/S`。macOS 使用官方 dmg/pkg；Linux 依据当前 deb/rpm/AppImage/tar 说明。用户无权限时选官方用户级/便携方式，必须提权才请求具体权限。
3. 按实际操作系统安装，确认安装器退出和应用路径。启动应用，完成账号流程和必要运行依赖。不能只用进程存在证明成功。
4. IDE/浏览器导入配置只在需要时最小选择，不默认导入全部密码、历史、网盘或仓库权限。
5. 按产品卡完成样例；重开一次检查入口与登录状态。更新系统 PATH 的场景重新打开终端或对子进程设置 PATH。

## CLI：终端编程工具

优先当前官方原生安装器；npm 是官方仍支持时的备选路线。下面三组包名在编写时有官方仓库依据，执行前检查当前 README 和 `engines`。

```sh
# 在官方仍支持 npm 且 Node/npm 满足要求时，AI 只执行用户选择的一组。
npm install --global @openai/codex
codex --version

npm install --global @qwen-code/qwen-code
qwen --version

npm install --global @anthropic-ai/claude-code
claude --version
```

- npm 全局目录无权限时采用官方原生安装器或用户级 npm 前缀，不默认 sudo。对包安装脚本先核对官方来源，保留现有其他 Node 环境。
- Kimi Code：先读 https://www.kimi.com/code/docs/en/kimi-code-cli/guides/getting-started 。当前资料说明已迁移到 Node.js；不能把历史 `uv tool install kimi-cli` 当默认安装。官网的 shell/PowerShell 安装脚本应先下载到私密临时目录、阅读所改范围，再执行；只采用当前 OS 对应地址，不机械替换后缀。
- Qoder、TRAE、Antigravity、ZCode、Harness：从各产品卡文档获取当前支持的 CLI/桌面形态，未提供 CLI 就选 APP，不猜 npm 包名。
- GLM Coding Tool Helper：按智谱当前文档核对 `@z_ai/coding-helper` 的来源、Node 要求和配置范围，再运行；只配置选定工具，不覆盖其他供应商默认设置。
- 登录使用工具当前 `--help` 或交互菜单支持的入口，OAuth 回调/设备码保留原任务。根据用户选择使用官方账户或兼容供应商，不能把 GLM 配进 Claude Code 后声称正在用 Claude 模型。
- 在临时目录写入一段简短样例，要求解释代码或创建一个 hello 文件。先看 CLI 帮助再选非交互参数；没有 `--print` / `exec` 等参数就不用虚构它们。
- 检查退出状态、输出和文件，再记录可重复启动命令。仅 `--version` 成功不足以证明模型可用。

## EXT：编辑器、浏览器、Office/WPS

1. 识别用户实际宿主与版本，查看其扩展机制；从品牌官网点击到市场，检查发行者、权限和支持系统。
2. 复用宿主已有账号；安装所选扩展，必要时重启扩展宿主并确认启用。不要从搜索结果直接安装同名非官方包。
3. 只授权一个临时项目/文档或当前网页。完成账户认证，检查扩展是否需要独立套餐。
4. IDE 中生成/解释样例；浏览器中归纳当前公开页面；Office/WPS 中编辑临时文件。保存、打开、确认结果。
5. 浏览器/Office UI 受远端会话隔离影响时，用目标交互桌面执行；SSH 能运行命令不代表能操作正在登录的桌面。

## API：托管模型与开发平台

1. 读产品卡官方平台。核对地区、个人/团队、项目、按量服务或编码订阅。普通 API 与 Coding Plan、聊天订阅通常独立，不假定互通。
2. 浏览器进入控制台，复用用户已有项目；新建仅任务所需的最小项目与密钥。使用安全输入或私密本地配置，勿把密钥传回聊天、命令行参数或提交仓库。
3. 从官方文档抄录当前完整端点、协议、精确模型 ID、认证头和必要版本头。地区不同端点可能不同。模型列表接口并非所有厂商都支持。
4. 配置用户所选应用的供应商，备份该应用的已有配置后局部合并。用官方 SDK 的最小示例验证对应协议，不把 Responses、Chat Completions、Messages、Gemini、WebSocket 和媒体任务接口混用。
5. 对标准文本协议可使用附带的 `scripts/api_probe.py`：默认仅生成不含密钥的调用计划；在有授权的少量调用场景传 `--execute`。密钥只从指定环境变量读。Gemini 等非通用协议按官方 SDK 示例运行。

```sh
# 这些参数必须用官方当前文档的真实值替换；不要直接运行占位值。
python scripts/api_probe.py --protocol openai-chat \
  --url https://OFFICIAL_HOST/EXACT_CHAT_ENDPOINT \
  --model EXACT_MODEL_ID --key-env PROVIDER_API_KEY
# 先确认计划与端点，再在原命令追加 --execute。
```

6. 图像：用当前图像接口生成小样例并查看；视频：保存创建任务 ID，按状态接口查询原任务到终结，下载成功产物；音频：生成/识别自有样例；实时接口：按原厂 SDK 完成会话和音频往返。`api_probe.py` 不覆盖这些专用协议，不能冒充通用安装器。
7. 错误处理：401 查密钥来源和认证头，403 查权限/区域，404 查 URL 和模型，429 查额度/速率，5xx 按退避重试；不要错误时自动换收费渠道。控制台充值或新订阅需具体授权。

## LOCAL：开放模型、专用推理与开放源码平台

### 语言、推理、视觉、代码模型

1. 从产品卡链接的官方组织找到精确模型卡。记录模型 ID、revision/版本、许可证、架构、量化来源和官方支持引擎；模型名不是可执行安装命令。
2. 判断 RAM/VRAM、磁盘和下载大小。权重体积之外预留上下文 KV cache、运行时和临时空间；不把参数位宽计算当完整显存保证。选择用户可接受且适合设备的版本；完整大模型不适配时说明可选小模型/蒸馏或云端路线，请用户决定关键取舍。
3. 运行器按模型卡选择：官方支持的 Ollama/llama.cpp（含 GGUF）、vLLM/SGLang 服务，或 Transformers 原厂示例。先核对平台支持；不能给原生 Windows 强装 Linux 专用 GPU 引擎并宣称可用。
4. 给出可直接执行的实际命令后由 AI 执行。Ollama 支持的确切 tag 可用 `ollama pull EXACT_TAG`、`ollama run EXACT_TAG`；vLLM 支持且已满足 CUDA/系统条件时可用 `vllm serve EXACT_HF_MODEL --host 127.0.0.1 --port SELECTED_FREE_PORT`。这些占位符必须由官方当前文档和实际空闲端口解析后替换。不要盲猜 tag 或硬编码占用用户端口。
5. 无运行器预制支持时，创建隔离 Python 环境：`python -m venv <独立目录>`，按模型卡安装准确版本，使用其 processor/tokenizer 和加载方式；`trust_remote_code` 仅在模型确需且审阅来源后启用。
6. 后台服务只绑定回环地址，保存自己创建的进程/服务记录；只有用户明确要求网络共享才另处理访问控制。运行模型的首个真实样例，确认输出和实际设备，然后保存启动/关闭入口。

### 图像、视频、语音专项

- Qwen-Image、CogView、Wan、CogVideoX、MiniMax 开放媒体模型：读取精确仓库的 Python/Diffusers/ComfyUI 等受支持路线；不要仅安装聊天运行器。若用 ComfyUI，仍须把官方 workflow、插件、权重及其路径装全并实际跑图/视频。
- CosyVoice、FunASR、Qwen 语音、Whisper、GLM 语音：隔离依赖，检查 FFmpeg/音频采样率和读写；下载对应模型；语音合成播放输出，识别则核对文本。音频硬件权限与离线文件推理分别验收。
- 任务时长较大时保留 job ID/输出目录，周期检查进度，不因一次工具等待结束重复启动。下载由目标电脑通过正常网络直接进行，不通过小型远端控制通道传输大权重。

### 开放源码应用（如 Coze Studio、Harness）

原厂仓库 README 是安装清单来源。核对 license、release、依赖与环境变量；使用独立目录、独立数据卷、私密配置。Compose 项目使用明确项目名，不操作用户其他容器。启动后检查服务日志、页面、模型供应商配置及真实业务流程；页面 200 只证明前端活着。退出时保留用户需要的实例，记录重启与备份方式。

## PHONE：Open-AutoGLM

1. 阅读当前官方 README；区分控制端、模型服务端和真实手机，不混淆三者位置。
2. 在控制端安装官方 Android 平台工具与独立框架环境；手机由本人授权 USB 调试。识别连接列表和目标设备序列号，不猜默认设备。
3. 仅在 README 要求时安装官方引用的输入法/辅助组件，并由用户完成手机侧必要授权。不要关闭安全锁屏或暴露调试端口到公网。
4. 配置已授权 API 或本地模型，先读取截图/界面确认目标，再运行“打开设置并查看关于手机”等无外部副作用任务。
5. 查看操作结果和最终屏幕；记录启动和断开方式。本人授权未完成时标记 blocked-auth。

## HISTORY：下线与迁移

官方公告优先于历史教程。保留旧名称的映射和事实日期；不安装冒名包。不再提供的能力不能标记 ready。用户接受当前替代路线后，再按对应产品卡执行，并在报告中说明更换了什么。

## 错误恢复

安装失败先读退出码、支持平台与官方故障页；浏览器失效先重新读取 DOM/可访问性树；队列未结束先查原任务；断线后先确认原目标身份与原任务状态。每次修复要有具体依据，避免无差别重装、删除用户配置、反复充值或重复提交收费任务。明确撤销权限、身份不匹配、缺少必需工具等情况应记录真实阻塞及最小补充条件。
